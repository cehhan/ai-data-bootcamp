# 궁·능 인력 배치 모형 비교

궁 4곳·종묘·조선왕릉 18곳(총 23개소)의 2026년 1월 관람객을 예측하고, 개소별 일일 인력 수를 정해 비용을 비교하는 저장소입니다.

- **비용 기준**: 모자라면 1명당 60만 원, 남으면 1명당 15만 원, 1명은 하루 2,000명을 담당
- **1순위 지표**: 총 비용(원). 보조 지표는 WAPE(%)와 적중률(%)

> 결과만 보고 싶다면 [`results/`](results/) 폴더의 CSV 파일을 여세요.

## 결과 요약 (2025년 원점 12개)

전체 모형(앙상블, Prophet, Chronos, ARIMA, SARIMA, ETS, 배율 행 3~7, 베이스라인 등)의 비용·WAPE·적중률 비교표는 엑셀에서 열 수 있는 [`results/모형_비교_전체.csv`](results/모형_비교_전체.csv)에 있습니다. 비용 순서로 정렬되어 있고, 최종 모형인 앙상블이 맨 위에 옵니다.

- 이 비교표의 비용은 소수 인원 기준입니다. 근무표 규칙(올림, 최소 1명) 기준은 [`results/백테스트_비용.csv`](results/백테스트_비용.csv)와 [`results/FVA_표.csv`](results/FVA_표.csv)를 보세요.
- 「제외」는 공휴일, 명절 연휴, 마지막 수요일을 뺀 날입니다.
- **적중률**: 필요 인력(실제 ÷ 2,000)이 배치 인력(예측 ÷ 2,000) 이하였던 날의 비율입니다. 예정 휴관은 0명 배치로 계산했습니다.
- SARIMA의 WAPE는 Colab 결과를 기준으로 합니다(아래 "재현할 때 알아 둘 점" 참고).
- 원점별 WAPE는 [`results/guide_per_origin_wape.csv`](results/guide_per_origin_wape.csv), 원점별 비용은 [`results/compare_per_origin.csv`](results/compare_per_origin.csv)에 있습니다.

## 모형 설명

| 구분 | 모형 | 설명 |
|---|---|---|
| 베이스라인 | 나이브, 계절 나이브 7일, 직전 7일 평균 | 과거 값으로 예측하는 단순한 규칙. 운영팀의 현재 방식은 직전 7일 평균 |
| 기준 보정 | 서비스 수준 보정 (행 2) | 직전 7일 평균에 과거 실제÷평균의 0.8 분위수를 곱함 |
| 배율 모형 | 행 3~7, 배율+월 | 로그 관람객을 선형 회귀로 추정. 피처를 누적해서 추가 |
| 머신러닝 | LightGBM | 나무 모형, 0.8 분위수 목표 |
| 통계 | ETS, ARIMA, SARIMA, Prophet | 시계열 통계 모형. 공휴일 등 외생변수 포함 |
| 사전학습 (제로샷) | Chronos-2 | 학습 없이 예측하는 사전학습 모형. 단변량과 달력 공변량 버전 |

**0.8 기준**: 배율 모형, LightGBM, 통계 모형, Chronos-2는 모두 0.8 분위수 기준으로 예측합니다. 직전 7일 평균과 나이브는 점 예측입니다. 0.8 기준끼리 비교하려면 서비스 수준 보정(행 2, 1,599,987,968원)을 기준으로 봐야 합니다.

**달력 정보**: 공휴일, 명절, 마지막 수요일, 예정 휴관은 지정 데이터셋의 달력 파일과 개소 정보에서 만들었습니다. 외부 데이터는 쓰지 않았습니다. 2026년 권고 날짜의 공휴일만 `holidays` 0.103 패키지로 계산했습니다.

## 설치

Python 3.12 이상을 권장합니다.

```bash
python -m venv .venv
# Windows
.venv\Scripts\activate
# macOS / Linux
source .venv/bin/activate

pip install -r requirements.txt
```

- `torch`는 용량이 큽니다. GPU가 없으면 CPU용 wheel을 쓰세요.
- Chronos-2는 처음 실행할 때 모델(약 480MB)을 Hugging Face에서 내려받습니다. 인터넷 연결이 필요합니다.

## 실행

```bash
python scripts/run_all.py                 # 전체 실행 후 비교표 출력
python scripts/run_all.py --skip chronos  # Chronos 제외
```

단계별로 실행할 수도 있습니다.

```bash
python scripts/run_classic.py   # 기준, 배율 모형, LightGBM  → output/pred_classic.csv
python scripts/run_stat.py      # ETS, ARIMA, SARIMA          → output/pred_stat.csv
python scripts/run_chronos.py   # Chronos-2                   → output/pred_chronos.csv
python scripts/compare.py       # 모든 예측을 같은 기준으로 비교
python scripts/compare_guide.py # 가이드 형식 비교표 (전체·제외, 적중률 포함)
python scripts/ensemble.py      # 앙상블 (Chronos+달력 과 Prophet 50:50) → output/pred_ensemble.csv
```

앙상블은 `output/pred_chronos.csv` 와 `output/pred_prophet.csv` 가 있어야 합니다. Prophet 은 로컬 Windows 에서 설치 오류가 나므로 Colab 에서 만든 `pred_prophet.csv` 를 `output/` 에 넣어 주세요. 두 파일이 없으면 스크립트가 안내 메시지를 출력하고 멈춥니다.

앙상블 결과 (2025년 원점 12개, 실제 휴관 제외): 총 비용 865,671,727원 (소수 인원 기준, 권고 규칙 기준은 1,467,420,150원), WAPE 39.5%, 적중률 82.0%.

재현 확인:

```bash
python tests/test_baseline.py   # 직전 7일 평균 비용이 1,702,786,555원인지 확인
python tests/test_leakage.py    # 누수 테스트 (미래 정보가 예측에 섞이지 않는지 확인)
```

누수 테스트는 다음 세 가지를 확인합니다.
1. **미래 교란**: 원점 이후의 관람객과 휴관 여부를 무작위로 바꿔도 예측값이 같아야 합니다.
2. **과거 감도**: 원점 이전의 관람객을 바꾸면 예측값이 달라져야 합니다(검사가 제대로 작동하는지 확인).
3. **입력 열 점검**: 모형 입력에 관람객이나 휴관 여부 같은 결과 값이 없어야 합니다.

대상은 베이스라인, 배율 모형(행 3~7, 배율+월), LightGBM, ETS, ARIMA, SARIMA입니다. Prophet과 Chronos-2는 실행 시간이 길어서 이 테스트에서 뺐습니다. 검사 원점은 2025-07-01 하나입니다.

## 평가 규칙

- **검증 기간**: 2025년 원점 12개 (매월 1일). 원점 전날까지의 데이터만 학습에 사용
- **평가 대상**: 실제 휴관일을 뺀 날
- **예정 휴관**(정기 휴관 요일, 휴관 이동일): 예측과 상관없이 0명 배치
- **인력** = 예측 관람객 ÷ 2,000명 (소수 그대로)
- **비용** = 60만 원 × 모자란 명 + 15만 원 × 남는 명 (하루 단위)
- **안전장치**: 통계 모형 예측값이 개소 과거 최대 개방일 관람객의 2배를 넘거나 무한대이면 그 상한으로 제한합니다 (모든 통계 모형에 동일 적용)

## 재현할 때 알아 둘 점

- **통계 모형 결과는 실행 환경에 따라 달라질 수 있습니다.** 특히 SARIMA는 Colab과 로컬(이 저장소 기준)에서 WAPE가 다르게 나왔습니다. 최적화 과정이 라이브러리 버전에 민감하기 때문입니다. `results/`의 값은 Colab에서 돌린 통계 모형 결과를 기준으로 합니다.
- **Prophet은 연간 계절성 경고가 나옵니다.** 일부 개소와 원점에서 개방일 기록이 2년 미만이기 때문입니다.
- **Chronos-2 결과는 실행마다 몇 원 정도 달라질 수 있습니다.** 로컬과 Colab 결과가 소수점 수준에서 다릅니다.

**9. `실수_측정_무료개방_개소별.csv` — 무료 개방일 판정 차이 (개소별)**
- 뜻: 무료 개방일을 달력 규칙(명절 연휴, 마지막 수요일)으로 정하면 유료 관람객 0(paid == 0)으로 정하는 것과 얼마나 다른지, 개소별로 보는 표. 실수 5번의 근거입니다.
- 한 행: 개소 하나(23행).
- 주요 열: `site`(개소), `개방일`(문을 연 날 수), `달력규칙`(달력 규칙으로 무료인 날 수), `paid0`(유료 0인 날 수), `달력과 paid0 불일치`(두 기준이 다른 날 수).
- 만든 스크립트: `mistakes.py --full`

**10. `권고표_2026_01.csv` — 2026년 1월 권고표 (긴 형식)**
- 뜻: 운영팀이 근무표에 옮기는 값. 날짜와 개소마다 인원 한 줄씩.
- 한 행: 날짜 × 개소 하나 (713행 = 31일 × 23개소).
- 주요 열: `모형`(앙상블 표시), `날짜`, `요일`, `구분`(궁/종묘/왕릉), `개소`, `예정휴관`(휴관이면 "휴관", 아니면 빈칸), `예측관람객`, `필요인원_소수`(예측 ÷ 2,000, 올림 전), `권고인원`(정수, 올림, 예정 휴관은 0, 영업일 최소 1명).
- 만든 스크립트: `forecast_2026.py`

**11. `권고표_2026_01_피벗.csv` — 2026년 1월 권고표 (피벗)**
- 뜻: 같은 권고표를 엑셀에서 보기 좋게 바꾼 표.
- 한 행: 개소 하나(23행).
- 주요 열: `개소`, 날짜 열 31개(`2026-01-01` ~ `2026-01-31`). 칸 값은 그날의 권고인원입니다.
- 만든 스크립트: `forecast_2026.py`

**12. `모형별_모자람_남음.csv` — 모형별 모자란 인원·비용과 남는 인원·비용**
- 뜻: 모든 모형을 같은 방식으로 계산해서, 모자란 쪽과 남는 쪽을 따로 보여 주는 표. 근무표 기준(권고 규칙)과 올림 전 소수 기준 두 가지가 들어 있습니다.
- 한 행: 규칙 하나 × 모형 하나 (모형 수 × 2행).
- 주요 열: `규칙`, `모형`, `모자란 인원(명)`, `모자란 비용(원)`, `남는 인원(명)`, `남는 비용(원)`, `총 비용(원)`, `직전 7일 평균 대비 절감(원)`, `직전 7일 평균 대비 절감 비율(%)`.
- 만든 스크립트: `shortage_by_model.py`

**참고**: `scripts/run_fva.py`는 `results/FVA_앙상블.csv`를 만듭니다. 열 구성은 `FVA_표.csv`와 비슷하지만 소수 인원 기준입니다.

## 알아 둘 한계

- 학습 기간이 2023년부터라 약 2년의 기록으로 계절성과 명절 효과를 추정합니다.
- 날씨 피처는 2026년 값이 없어 권고에 쓸 수 없으므로 비교에 넣지 않았습니다.
- 모든 비교는 2025년 원점에서 이뤄졌습니다. 2024년 원점에서의 검증은 아직 하지 않았습니다.
- Chronos-2는 사전학습 모형을 그대로 쓰는 제로샷 예측입니다. 우리 데이터로 추가 학습(파인튜닝)하지 않았습니다.
- 적중률과 WAPE는 같은 결과를 다른 관점에서 본 것입니다. 보고서에는 두 지표를 함께 적어야 합니다.
